# 案例：重写一个「周复盘自动化」提示词（9 条病根诊断）

> 真实案例。一份定时自动化任务（每周扫知识库 → 生成复盘报告 → 推送到手机）反复产出"水分很大、看不到真实痛点"的报告，用户明确差评后，对原提示词做了一次系统性诊断与重写。
> 这个案例的价值：**自动化提示词的坑是相通的**——照着这 9 条自查，能躲掉大多数"AI 产出正确废话"的问题。

---

## 一、病根诊断

用户核心反馈：**"水分很大，体现不了真实现状和痛点，希望更贴近原始笔记"**。

| # | 问题 | 后果 |
|---|------|------|
| 1 | **prompt 全程没提"读正文"**，只让用列表接口 | 拿到的是系统自动生成的**摘要**，不是用户写的原文。在二手摘要上再做一次 AI 加工 = 两层抽象叠加 = 正确的废话。**这是水分的根源** |
| 2 | 要求"关键认知突破 1-3 条""从笔记语气推断状态/精力" | 硬性数量 + 允许推断 = 直接邀请模型编造 |
| 3 | 分页参数是必填项，prompt 示例里没写 | 调用可能失败或只返回默认少量条目，扫漏数据 |
| 4 | ID 参数写法与接口约定不一致（缺前缀） | 可能报"不存在"，任务直接失败 |
| 5 | 推送用命令行内联 JSON | 中文编码被破坏，必然乱码 |
| 6 | 上传只说"传到返回的凭证地址" | 手动签名方案已知会 403，应指向更稳的 SDK 方案 |
| 7 | 时间窗口说法自相矛盾（"回推 7 天" vs 示例区间） | 报告命名与实际覆盖对不上 |
| 8 | 防重复只查云端列表 | 写入成功但列表可能延迟为空 → 重复生成 + 重复推送 |
| 9 | prompt 与已沉淀的踩坑记录完全脱节 | 之前修好的坑，prompt 还在踩 |

**第 1 条是核心**：列表接口的摘要字段是"AI 加工过一次的抽象"，拿它当素材 = 在二手信息上做二手加工。所有报告类任务的通病。

## 二、设计决策（重写时定下的原则）

- 时间窗口 = `[运行日-7, 运行日-1]`，共 7 个自然日，含头含尾
- 防重复 = 本地文件 + 云端查询**双校验**（任一命中即停止）
- 输入必须是**原文**；输出**保持概括不摘录大段原文**，但**严禁升华推演**
- 对比报告改为**证据驱动**：给不出证据就写"数据不足，不判断"，禁止凭感觉贴标签
- 笔记少的周**如实说，不硬凑、不拉长窗口**
- 建议**不强制**绑定方法论，就事论事

## 三、重写后的 prompt 骨架（可直接套用）

```text
你是 <用户> 的每周复盘助手。

核心原则：报告必须建立在原始笔记正文之上。宁可短、宁可承认数据不足，也绝不写没有依据的话。

【第一步】先加载 <知识库操作 skill>——里面有一堆已验证的坑（上传、推送防乱码、ID 变更等）。
执行中遇到报错，先查 skill 的"已知问题与修复记录"；发现新坑，跑完把它补进 skill。

【目标数据源】
- 知识库 ID：<KB_ID> ／ 存档文件夹：<FOLDER_ID> ／ 本地存档目录：当前工作目录

【时间窗口】
区间 = [运行日-7天, 运行日-1天]，共 7 个自然日，含头含尾。
先用 date 命令取真实当前日期，不要凭空推算。
文件名：复盘_YYYY-MM-DD_YYYY-MM-DD.md

【Step 0 · 防重复双校验】
a) 查本地是否已有 复盘_<本次区间>.md
b) 列云端存档文件夹
任一命中 → 本周已生成，直接结束，不重复生成、不重复推送。

【Step 1 · 抓原文（决定报告质量的一步）】
1. 逐文件夹取区间内条目（注意分页参数写法、上限、倒序遍历早于起点的条目即停）
2. 对每条落在区间内的笔记，必须调"读正文"接口读全文。
   ⛔ 绝对不允许只靠列表接口的摘要字段写报告——那是系统自动生成的摘要，不是用户原话。
   基于摘要写出来的复盘全是正确的废话。读不到正文的条目单列为"未能读取正文"。
3. 建内部素材清单（不进最终报告）：每条记 标题 / 日期 / 来源 / 原句（带判断、疑问、情绪、待办的句子）。
   后续每个结论都必须能追溯到这份清单。

【Step 2 · 历史基准】
取区间早于本次的最新一份报告，读它的**正文**作对比基准。
无历史报告 → 注明"首次运行，暂无对比基准"，跳过对比部分。

【Step 3 · 写报告：反水分是第一优先级】

⛔ 硬性禁令，违反即重写：
- 不写"这体现了你在 XX 方面的成长/进步/思维升级"这类拔高句
- 不写素材里没有的推论，只陈述明确记录过的事实
- 不用"深度思考""认知跃迁""系统性提升"这类空词
- 不为填满模板而扩写；某板块没料就写"本周无"
- 不摘录大段原文，但每个结论都要能在素材清单找到出处；写不出出处的结论直接删

报告 A：本周实况
· 实际做了什么：按主题归纳，每条标注来源。
· 想通了什么：严格标准——只有素材里出现"原来/我发现/想明白了/关键是"这类明确表述才算。
  找不到就写"无明确认知突破记录"，不许硬凑。
· 进行中任务的进展：有数字写数字，没有写"未记录具体进展"。
· 卡点与未闭环（重点板块）：明确写出的困惑；反复出现在多篇里的同一问题（标注次数与篇目）；
  开了头没写完 / 有问号没答案 / 待办没打勾的条目。

报告 B：状态对比（证据驱动）
逐维度标 提升 / 持平 / 下滑 / 数据不足。每个维度必须附具体证据（数量对比、具体篇目）。
给不出证据一律写"数据不足，不判断"。「状态/精力」只在有直接表述（累了/焦虑等原话）时才判断，
禁止从行文语气脑补。

建议：2-4 条，就事论事，只针对报告 A 的具体卡点。
每条必须是"下周能直接做的一个动作"，不是"要加强 XX 意识"。
不强制引用库内方法论——套不上就别扯。

【空周处理】有效笔记 ≤ 3 条：如实写"本周输入很少，只有 X 条"，报告就短。不拉窗口凑数。

【Step 4 · 推送精简版】
500-1000 字，手机可读：一句话实况 + 维度对比（带证据数字）+ 1-2 个卡点 + 建议 + "完整报告见 <存档位置>"。

【Step 5 · 存档】先写本地（下次防重复的依据）→ 建媒体记录 → 上传对象存储 → 加入知识库。
⚠ 加入成功后列表接口可能仍返回空（缓存延迟），不必重试、不必重传。

【Step 6 · 推送】⛔ 禁止命令行内联中文 JSON（会乱码）。用 SDK / 请求库 / UTF-8 文件方式。
推送后检查返回状态；失败重试一次，仍失败在最终回复中明确说明。

【风格】诚实 > 好看。可以直说"这周没什么产出"，可以直说"这个卡点已经卡了三周了"。
只引用真实存在的内容——任何编造都算这次任务失败。
```

## 四、附带动作：同步把教训沉淀进 skill/知识库

重写 prompt 的同时，把本次诊断出的核心症结写进配套的 skill 文档（不是只改 prompt 就完事）：
1. **步骤编号断裂**：文档步骤跳号 → 重新编号
2. **补必填参数说明**：调用示例漏了必填参数 → 补全 + 分页写法
3. **补最关键一条原则**：在显著位置加粗写明「必须读正文，摘要字段会产出空话」——核心症结必须沉淀

## 五、通用启示（不看具体技术也成立的 5 条）

1. **摘要套摘要 = 废话**：任何"AI 处理 AI 产物"的链条，每多一层抽象就多一层失真。报告类任务必须回到一手数据
2. **硬性数量要求 = 邀请编造**："写 1-3 条 XX"会让模型没料也凑料。改成"没有就写无"
3. **防重复要双保险**：云端有缓存延迟，本地文件是最可靠的第二道锁
4. **prompt 和踩坑记录必须同步**：skill 里修好的坑，prompt 还在踩，等于没修
5. **让模型"宁可短"**：把"诚实 > 好看"写进 prompt，比任何质量要求都管用
